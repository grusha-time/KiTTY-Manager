# Установка, первый запуск и обновление

## 1. Подготовить приложение

Нужна Windows x64 и доступ к SSH-серверам — напрямую, через VPN или через настроенные точки входа. Готовый ZIP содержит .NET, KiTTY и Ansible runtime. Firefox и WinSCP устанавливаются отдельно только при необходимости.

1. Скачайте `KiTTYManager-2.0.0-windows-x64.zip` из раздела Releases репозитория.
2. Полностью распакуйте его в свою папку, например `C:\Tools\KiTTYManager`.
3. Запустите `KiTTYManager.exe` обычной учётной записью Windows. Папка должна разрешать запись: рядом появится `Data` с конфигурацией.
4. Не удаляйте `KiTTY` и `Runtime\Ansible`. Инструкции и примеры находятся в репозитории, отдельно от релизного ZIP. Для чтения без доступа к GitHub заранее скачайте исходники репозитория и откройте этот файл либо `wiki\Home.md` редактором Markdown/текста. «Справка по полям» встроена в приложение.

Необходимость прав администратора для настройки виртуализации не означает, что менеджер нужно постоянно запускать от администратора. Для обычных SSH-сессий виртуализация не нужна.

## 2. Выбрать сценарий подключения

### Сервер доступен непосредственно с ПК

1. Создайте новую сессию через меню или импортируйте готовую KiTTY-сессию.
2. Заполните карточку: имя `Тестовый сервер`, адрес `192.0.2.10`, порт `22`, логин `operator` и свой пароль/ключ. Эти адрес и логин — примеры, замените их своими.
3. Включите **«Сначала подключаться напрямую, без JH»**, нажмите **«Сохранить изменения»**.
4. Дважды нажмите сессию. Если используется ручная проверка host key, сверьте отпечаток с администратором сервера.

Если сеть доступна только после VPN, сначала подключите VPN. Менеджер сам VPN не создаёт.

### Сервер доступен через jumphost

Jumphost (JH) — промежуточный SSH-сервер. Точка входа менеджера — SOCKS5-сервис, через который начинается маршрут.

1. Создайте сессию самой JH с её SSH-адресом, портом и учётной записью.
2. Откройте **«Меню → Настройки точек входа…»**, добавьте точку и выберите эту jumphost-сессию.
3. Для SOCKS5, запускаемого на ПК, используйте `127.0.0.1`; включите выбор свободного локального порта и запуск сессии при недоступном SOCKS5.
4. Если JH требует OTP, заполните TOTP и приглашение. Если после входа нужна команда доступа, укажите её и настройте повтор пароля только при реальной необходимости.
5. Сохраните настройки. Предложение при запуске приложения помогает включить ещё неготовые входы.
6. Создайте сессию целевого сервера и выполните умное подключение. Для следующих переходов постройте связи между доступными серверами.

Не путайте **SSH-порт JH** с **локальным портом SOCKS5**. Поля точки входа подробно описаны в [Jumphost](Jumphost.md).

### Уже есть внешний SOCKS5

Укажите адрес и порт работающего SOCKS5-сервиса в точке входа. Не назначайте произвольную сессию для его запуска. Доступность TCP-порта ещё не доказывает готовность: нужен корректный ответ SOCKS5. Требования к сети и авторизации сервиса должен обеспечить его владелец.

## 3. Импортировать имеющиеся сессии

**Папка KiTTY** и **JSON менеджера** — разные источники:

- Для portable KiTTY выберите папку сессий при импорте. Проверьте перенесённые адреса, пути ключей, команды и login script: файл на старом ПК может не существовать на новом.
- Для JSON откроется мастер сопоставления. Сначала просмотрите группы/сессии/поля, затем применяйте решения. Одного совпавшего IP недостаточно, особенно в разных закрытых сетях.

Сохранение карточки обновляет менеджер. Изменения исходной KiTTY применяются отдельно либо автоматически при включённой настройке немедленной записи. См. [Экспорт, импорт и синхронизация](Export-Import.md).

## 4. Открыть веб-панель или SFTP

**Firefox:** установите браузер, откройте обычный профиль хотя бы один раз, затем закройте его перед копированием. В настройках менеджера оставьте автопоиск профиля или укажите исходную папку вручную. Добавьте в сессию полный URL панели. «Адрес DNS» заполните только для явного соответствия домена внутреннему IP.

Каждое веб-окно работает с временной копией. Новые сохранённые пароли и принятые исключения сертификатов из неё не вернутся в исходный профиль. Логин/пароль в таблице веб-панелей — подсказки, не автоматический ввод в сайт.

**WinSCP:** установите его или задайте путь к `WinSCP.exe` в настройках; используйте **«Открыть в WinSCP»** у выбранной сессии. Маршрут обслуживает менеджер, поэтому не завершайте его во время передачи файлов.

Подробности: [Веб-интерфейсы и WinSCP](Web-Interfaces.md).

## 5. Выполнить первую массовую задачу

Откройте кнопку **«Массовые задачи»** на верхней панели. Начните с одного тестового сервера и [готовых учебных примеров](examples/batch-tasks/README.md) из репозитория.

- **Конструктор:** откройте `.kmtask`, просмотрите действия/пути, выберите сервер, запустите и проверьте итог и файлы в Downloads.
- **Ansible:** сохраните папку примера целиком, проверьте готовность Ansible и выберите playbook. `hosts: all` означает выбранные в интерфейсе серверы. `localhost` в playbook — встроенная VM, не Windows.

WHPX требует доступной виртуализации и соответствующих компонентов Windows. Окно готовности показывает обнаруженную причину; оно не изменяет системные настройки автоматически. Не устанавливайте WSL/Docker только ради встроенного Ansible.

[Руководство по массовым задачам](Batch-Tasks.md) объясняет каждый тип действия, файлы, ошибки, права, туннели, ограничения runtime и дополнительные проверки.

## 6. Обновить установленный менеджер

1. Завершите задачи, закройте зависимые веб/SFTP-подключения и полностью выйдите из менеджера. Скрытое окно в трее — ещё работающий процесс.
2. Скопируйте старую папку приложения в отдельный backup. Нужны как минимум `Data` и ваши материалы `KiTTY`, но полная копия удобнее для отката.
3. Распакуйте новый ZIP в отдельную папку. Перенесите в неё старую `Data` и пользовательские `KiTTY\Sessions`/`KiTTY\Script` и ключи, если храните их там. Не заменяйте новый `Runtime\Ansible` старым набором файлов.
4. Запустите новую копию той же учётной записью Windows и проверьте пути в настройках, сессии, один маршрут и используемые интеграции.
5. Старую папку удаляйте после проверки. Для отката закройте новую версию и вернитесь к полному backup, а не смешивайте exe и конфигурации разных версий.

Конфигурация мигрирует при загрузке. В текущей миграции до схемы 9 у старых резервных адресов `InternalOnly` сбрасывается: после обновления проверьте отметки «Внутренняя подсеть».

## 7. Перенести на другой ПК или другого пользователя

До переноса выполните **«Экспорт JSON…»** на старом компьютере. Переносимый JSON содержит секреты открытым текстом; передавайте и храните его соответственно. На новом ПК установите менеджер, импортируйте JSON, заново проверьте локальные пути и при необходимости скопируйте закрытые ключи отдельно. Зашифрованный `Data\config.json` нельзя считать переносимым между учётными записями.

## 8. Где искать помощь

В приложении: **«Меню → Справка по полям…»**. Можно выбрать раздел или искать по всему содержимому (`Ctrl+F`), например `root пароль`, `Firefox профиль`, `backup`.

В документации: [навигация](Home.md), [типичные проблемы](Troubleshooting.md), [что хранится в Data](Configuration.md). При обращении за помощью укажите действие, ожидаемый результат, фактическую ошибку и приложите проверенный журнал. Не отправляйте полный config, экспорт или закрытые ключи.
