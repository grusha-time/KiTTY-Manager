# Как выбирается маршрут

Менеджер решает две задачи: **через какие серверы пройти** и **по какому адресу подключиться к каждому из них**. Группа в списке — организационная папка, не сетевой маршрут.

## Примеры

```text
Прямой сервер:  ПК → сервер
Через вход:    ПК → SOCKS5/JH → сервер
Несколько SSH: ПК → SOCKS5/JH → сервер A → сервер B
```

На каждом SSH-переходе нужны рабочая авторизация и доступ к следующему адресу. Сохранение стрелки на карте не настраивает firewall или разрешение SSH forwarding на сервере.

## Управление выбором

- **«Сначала подключаться напрямую, без JH»** разрешает сначала настоящую SSH-попытку с ПК. При неуспехе остаются подходящие резервные связи.
- **«Маршрут через»** задаёт безопасный промежуточный вход к конкретной цели. Полезно, когда один частный IP повторяется в разных сетях. Альтернатива должна быть подтверждена отдельной связью.
- Включённые **точки входа** образуют доступные входы. Выключенная точка не должна выбираться как обычный кандидат.
- **Построение связей** добавляет сведения о достижимости между серверами. Для многошагового пути нужны подходящие последовательные направления.

## Что запоминается

Успешный маршрут сохраняет цепочку серверов, использованную точку входа и измерение задержки. Рабочий IP:port запоминается отдельно для контекста входа/предыдущего сервера. Это помогает не перебирать все варианты при каждом открытии.

Сначала может использоваться уже рабочий путь. Фоновые проверки ищут более короткие и предпочтительные варианты, если топология изменилась. Поэтому немедленное открытие по старому рабочему пути и последующее обнаружение более короткого не обязательно ошибка. Уже открытая консоль не переносится автоматически на новую цепочку.

Ранжирование учитывает подтверждённость, длину, задержку и сведения о точках входа. Это не обещание всегда выбрать сервер с самым коротким названием или только минимальный ping.

## Основной и резервные адреса

1. Рассматриваются основной адрес и применимые резервные строки.
2. Подтверждённый адрес данного контекста может быть первым.
3. Перед SSH выполняется короткий зонд адреса; недоступный адрес позволяет перейти к следующему.

Пустой IP резервной строки означает основной хост. Изменённый/удалённый адрес не должен оставаться обязательным только из-за кеша.

**Внутренняя подсеть** разрешена после другого сервера и запрещена на первом переходе от ПК/JH. Например адрес B, видимый только с A, следует пометить внутренним; одной такой отметки недостаточно — нужен доступный путь через A.

## Таймауты и неудачи

В настройках отдельно задаются таймаут этапа подключения (3–600 с), зонд одного адреса (1–30 с), лимит вариантов маршрутов (1–100, по умолчанию 20) и максимум независимых серверов одной группы при переборе маршрутов (0–100, по умолчанию 2). Лимит вариантов ограничивает суммарное число перебираемых цепочек и точек входа при одном подключении, а лимит серверов группы защищает от монополизации очереди: если к целевому серверу ведут пути через большую группу (например, из 15 серверов), менеджер проверит лучший маршрут через ограниченное число серверов этой группы (по умолчанию 2) и перейдёт к проверке независимых путей через другие группы. Значение 0 отключает групповое ограничение. При исчерпании общего лимита перебор останавливается с понятным сообщением в журнале. Недавние неудачи кратковременно кешируются, чтобы не повторять заведомо плохие попытки; неудача прямого входа не должна блокировать пригодный обходной многошаговый путь.

При задачах действует ещё ожидание восстановления связи. Если удалённая команда могла выполниться перед обрывом, её автоматический повтор не всегда безопасен: менеджер может запросить решение пользователя. При этом исчерпание лимита маршрутов не считается временным сбоем связи и не приводит к бесконечному циклу автовосстановления задачи.

## Если выбран не тот путь

1. Проверьте «Маршрут через», прямой флажок, состояние JH и одинаковые IP в разных сетях.
2. Посмотрите направления и последние результаты в «Сохранённых связях».
3. Перепроверьте нужную пару, а не просто переставляйте группы.
4. Включите журнал и найдите фактическую цепочку и адрес отказавшего этапа.

Полный выход из менеджера разрывает обслуживаемые им цепочки. Для сохранения работы используйте сворачивание в трей. [Карта связей](Link-Map.md) · [Диагностика](Troubleshooting.md).
