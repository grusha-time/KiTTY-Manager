# Сессии, настройки и данные

Настраивайте приложение через интерфейс. Ручное редактирование `config.json` обычно не нужно и может нарушить ссылки между объектами или защиту секретов.

## Карточка сессии

| Поле | Что указать / как использовать |
|---|---|
| Название | Удобная подпись, например «Сервер приложения» |
| Адрес, SSH-порт | IP/DNS без ssh:// и порт SSH, обычно 22 |
| Логин, пароль | Учётная запись для первого SSH-входа |
| Ключ SSH | Локальный закрытый ключ PPK/PEM. Относительный путь считается от папки приложения |
| Пароль ключа | Passphrase файла ключа, не пароль пользователя |
| Повышение прав | `su -`, `sudo -i`, `sudo su -` или пусто. Права должны быть настроены на сервере |
| Root-пароль | Пароль, который запрашивает su/sudo; для sudo это может быть пароль исходной учётки |
| Скрипт KiTTY | Источник импортированного login script; нестандартные скрипты нужно проверять вручную |
| Shell prompt | Устойчивая подстрока приглашения для отправки повышения прав, не regex |
| Команда KiTTY | Autocommand после входа; можно изменить или очистить |
| Не выполнять команду KiTTY при умном подключении | Отключает Autocommand в маршруте менеджера, но не отключает повышение прав |
| Маршрут через | Промежуточная сессия для данной сети. Особенно важно для одинаковых private IP в разных сетях |
| Сначала подключаться напрямую, без JH | Сначала попытка SSH с ПК, затем подходящие резервные маршруты |

Если заполненный путь ключа перестал существовать, исправьте его: нужный ключ не будет использован. Не считайте пароль ключа заменой самого файла.

**Сохранить изменения** обновляет менеджер. Запись в portable KiTTY выполняется отдельно через «Изменения KiTTY…» либо автоматически при включённой настройке. Исходные файлы KiTTY поэтому **могут изменяться** при явном применении.

## Резервные адреса

Добавляйте адреса того же сервера, а не соседние серверы. Пустой IP означает основной хост. Новый порт — 22. **«Внутренняя подсеть»** запрещает использование этой строки первым переходом от ПК/JH; адрес становится применим после другого сервера.

Успешный адрес запоминается для конкретного входа/предыдущего сервера. Удалённая или изменённая строка не должна заставлять менеджер продолжать использовать старый порт. Подробнее — [Маршрутизация](Routing.md).

## Группы и дублирование

Группы/подгруппы организуют список и групповой выбор. При удалении группы её сессии остаются в «Без группы»; удаление сессии из менеджера не удаляет её исходный файл KiTTY. Они сами не создают VPN, маршрут или правило доступа. Перетаскивание меняет принадлежность сессии.

**Обычное дублирование** копирует настройки с новым ID. **Быстрый дубль** открывает немодальный редактор нового сервера, очищает состояние подключений, host key, резервные адреса и веб-панели. После сохранения может построить направление от выбранных входных узлов к новому дублю. Не путайте копирование карточки с клонированием удалённого сервера.

## Настройки приложения

| Настройка | Поведение |
|---|---|
| Путь к KiTTY / Firefox / WinSCP | Исполняемые файлы. WinSCP можно искать автоматически при пустом поле |
| Автопоиск профиля Firefox | По умолчанию включён; используется готовый профиль из profiles.ini |
| Шаблон профиля Firefox | В ручном режиме — **исходная папка**, а не общий профиль менеджера. Нужны key4.db и cert9.db |
| Таймаут одной попытки | 3–600 с, по умолчанию 10. Не ограничивает срок жизни открытой консоли |
| Лимит зонда одного адреса | 1–30 с, по умолчанию 4. Короткая проверка IP:port |
| Ожидание восстановления задач | 0–99999 минут, по умолчанию 1; повторы через 10 секунд, затем продлить/остановить |
| По крестику скрывать в трей | Менеджер остаётся работающим; полный выход — другое действие |
| Записывать журнал | Включает диагностический manager-log без перезапуска; по умолчанию выключен |
| Записывать изменения сразу в KiTTY | После сохранения карточки обновляется встроенный файл сессии |
| Закрывать консоль веб-туннеля после Firefox | По умолчанию выключено; относится к консоли соответствующего веб-подключения |
| Автоматически доверять host key | По умолчанию **включено**, в том числе для изменённых ключей; отключите для ручной сверки |
| Не показывать уведомления KiTTY при запуске | Скрывает уведомления, но не список отличий в меню |
| Параллельно проверять две лучшие точки входа | По умолчанию выключено; дополнительная конкурирующая попытка для готовых входов |
| На карте проверять только новые связи | По умолчанию включено для соответствующего режима; явная перепроверка связи остаётся доступной |
| Предлагать запуск незапущенных точек входа | По умолчанию включено; не повторяет запуск уже готовых JH |

## Где хранятся данные

| Путь | Назначение |
|---|---|
| `Data/config.json` | Сессии, группы, связи и настройки. Защищены секретные поля, не весь JSON целиком |
| `Data/jumphost-consoles.json` | Сведения о процессах JH для восстановления учёта |
| `KiTTY/Sessions`, `KiTTY/Script` | Portable-сессии и их материалы |
| `Data/Tasks` | Шаблоны конструктора |
| `Data/Templates` | Рабочие папки Ansible-задач |
| `Data/Downloads` | Выгрузки по сессиям; для Ansible можно выбрать другую папку |

Временные runtime/профили/секретные helper-файлы не являются backup пользовательских данных. Для обновления сохраняйте закрытую старую папку приложения. Для переноса на другой компьютер нужен [экспорт JSON](Export-Import.md).

## Секреты и доверие

Windows DPAPI привязывает секреты к учётной записи и компьютеру. Экспорт JSON специально переносим и поэтому содержит открытые секреты. Логирование маскирует известные пароли, но произвольный вывод команд нужно проверять перед публикацией. Временные файлы и аргументы внешних процессов тоже нельзя считать отдельным зашифрованным хранилищем.

При загрузке старого конфига выполняется миграция. Для схем ниже 9 сбрасываются старые `InternalOnly` у резервных адресов; проверьте эти отметки после обновления. Самостоятельно понижать SchemaVersion не следует.
