# Автотесты: запуск, границы и аудит

Этот раздел предназначен разработчикам и проверяющим сборку. Для проверки программы без кода используйте [учебные задачи](Batch-Tasks.md) и [типичные проблемы](Troubleshooting.md). SelfTest запускается из исходников и не входит в пользовательский ZIP.

Тесты проверяют конкретные договорённости кода; они не гарантируют, что все внешние приложения и сети работают. После обновления сверяйте число выполненных тестов с фактическим выводом, а не с историческим числом ниже. Поиск новой встроенной справки защищает отдельный `HelpSearchFindsFieldsAcrossSections` в HelpTests.cs.

## Зафиксированный аудит 9 сентября 2026

Срез исходного набора: `9841078`, 339 зарегистрированных offline-тестов. Проверены все регистрации, тела тестов, вызовы кода/вспомогательных проверок и результат базового запуска. Спорные случаи проверены по текущим вызывающим методам. После изменений: **341 тест — удалены 4 устаревших, добавлены 6, остальные сохранены либо усилены**.

Это аудит тестов и ограниченный мутационный эксперимент, а не измерение покрытия каждой строки продукта. Матрица ниже содержит каждый оставленный на момент аудита тест; отдельная таблица — каждое удаление. Столбец кода построен по ссылкам из тела теста/его helper, а не по runtime coverage profiler. Наличие `ManagedServer` в этом столбце само по себе не доказывает покрытие всех методов модели.

## Существенные результаты

- Три теста кеша не имели проверок: только вызывали `ClearFailureCache`. Они заменены проверками состояния, TTL, изоляции и очистки обоих кешей самого SSH-сервиса. Для доступа к закрытым кешам используется reflection в тесте; API приложения ради тестов не менялся.
- Мутация удаления защиты `CreatedForRun` пережила старый `AnsibleTaskDeletionGuard`. Добавлены существующая пользовательская папка, соседняя папка с общим префиксом и запрет удаления корня; проверяется сохранность контрольных файлов.
- Два Ansible-теста проверяли старый in-memory упаковщик, который не вызывается исполнителем. Теперь вызывают `CreateTemporaryFileAsync`, реально используемый перед отправкой в VM.
- Тест нескольких источников повторял split вместо вызова кода продукта. Он переведён на `ParseLocalSources`.
- Новые проверки: неравномерные чтения и различия после границы буфера/в хвосте; ZIP traversal; schema-9 migration и повторная миграция; неполный Firefox source; опасные/повторные имена Ansible uploads и уборка при ошибке; отказ настоящего BatchTaskRunner от неправильного выбора до SSH.
- Проверки файлового сравнения и double-click перенесены из теста хранилища шаблонов в профильные тесты. Assertions не удалены без замены.
- Тест восстановления JH-процесса ранее безусловно вызывал Unix-only API. Теперь подготавливает платформенный тестовый процесс и завершает его дерево с ожиданием; Linux-ветка проверена, Windows-ветка требует Windows runner.
- Имена нескольких тестов уточнены: проверка строк не доказывает real-time вывод; диагностический SOCKS parser не является handshake приложения; копия Firefox имеет исключения.
- Старые публичные API без прямого вызова из текущего UI отмечены **legacy API**. Их самостоятельные контракты сохранены осторожно; не выдаются за проверку заменившего их интерфейса. Неиспользуемый production-код в рамках аудита не удалялся.

## Запуск и сопровождение

Из корня репозитория:

```sh
dotnet run --project src/KiTTYManager.SelfTest
# Список без выполнения:
dotnet run --project src/KiTTYManager.SelfTest -- --list
# Подстрока имени метода или названия; несколько фильтров через запятую:
dotnet run --project src/KiTTYManager.SelfTest -- --filter FailureCache,AnsibleTaskDeletion
python3 scripts/test-audit/mutate.py
```

Пустой/неизвестный фильтр не даёт ложного успешного прогона. Фильтр с отсутствующим значением завершается кодом 2, без совпадений — кодом 1. В FAIL теперь видны имя метода и стек исключения.

Мутации перечислены в [mutations.json](https://github.com/grusha-time/KiTTY-Manager/blob/master/scripts/test-audit/mutations.json). Скрипт использует стандартный Python и установленный .NET, без нового тестового фреймворка. Он копирует `src`/`examples` в отдельный временный каталог, проверяет baseline, вносит одну поломку, собирает, запускает соответствующие тесты и восстанавливает файл в копии. Рабочие исходники не мутируются. `--only id1,id2` ограничивает набор; `--output` задаёт JSON-отчёт.

`killed` — собравшаяся мутация вызвала FAIL; `survived` — выбранные проверки её пропустили; ошибки сборки, тайм-ауты и ошибки инфраструктуры не считаются обнаруженными поломками. Смена исходного фрагмента требует пересмотра мутации, а не молчаливого пропуска. Процент для этого набора нельзя называть процентом покрытия всей программы.

Подробные журналы: `TestResults/test-audit/`. Результаты окончательных запусков приведены в итоговом разделе этого документа.

## Географические примеры

Проверены исходники тестового проекта: русские названия регионов/административных центров, латинские варианты, основы склонений и распространённые сокращения. Просмотрены совпадения по словарю из 283 вариантов/основ и дополнительным сокращениям. Реальных названий не найдено; совпадения с обычными словами чтения отвергнуты вручную. `Region-A`, `Region-B`, «Регион», «Подгруппа» — абстракции, сохранены. Словарь реальных названий намеренно не добавлен в репозиторий. Это проверка исходных тестовых данных, не содержимого сторонних бинарных зависимостей.

## Что эти проверки не гарантируют

- Запуск Windows WPF, корректный клик/Shift/drag и внешний вид контролов: тестируются политики, не реальные события окна.
- Полный lifecycle Firefox, KiTTY/WinSCP, QEMU/WHPX, реальный парольный `su`, отмена/обрыв SSH на удалённом стенде. PTY-тест использует управляемый поток, ConfigStore — тестовую реализацию защиты секретов; это не проверка Windows DPAPI.
- Отправка чанков через настоящий serial bridge и выполнение всех шагов BatchTaskRunner по SSH. Добавленная проверка исполнителя защищает preflight, а не заменяет SSH E2E.
- Все сценарии восстановления/гонок и произвольные сторонние коллекции Ansible.

`--live` и `--diagnostics` существуют отдельно и могут обращаться к настроенным серверам/процессам. Они не запускались автоматически в этом аудите. Для Windows/VM остаётся отдельный интеграционный стенд; учебные задачи помогают его проверять, но не заменяют регрессию.
