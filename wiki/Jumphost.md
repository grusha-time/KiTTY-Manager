# Точки входа и jumphost

Точка входа — SOCKS5-сервис, доступный с вашего ПК. Он может быть запущен KiTTY через jumphost-сессию или уже существовать как внешний сервис. SSH-порт удалённого JH и локальный SOCKS5-порт — разные вещи.

## Настроить запуск через JH

1. Создайте SSH-сессию входного сервера и проверьте её адрес, порт и авторизацию.
2. Откройте **«Меню → Настройки точек входа…»**, добавьте точку, назначьте эту сессию и включите её.
3. Для локального SOCKS5 укажите `127.0.0.1`, разрешите выбор свободного порта и запуск сессии при недоступном SOCKS5.
4. Заполните OTP/команду доступа только если они действительно требуются сервером.
5. Сохраните и выполните умное подключение к тестовой цели. Проверьте не только консоль JH, но и достижимость цели.

Для внешнего SOCKS5 задайте его реальный адрес/порт. Не назначайте случайную jumphost-сессию только ради заполнения поля.

## Поля точки входа

| Поле | Назначение |
|---|---|
| Включён | Разрешить использование в маршрутах |
| Название | Понятная подпись входа |
| Сессия jumphost | SSH-сессия, которую KiTTY запускает для создания SOCKS5 |
| Адрес / порт | SOCKS5 со стороны ПК; это не адрес/порт SSH самой JH |
| Запускать сессию, если SOCKS5 недоступен | Разрешает запуск назначенной сессии по необходимости |
| Выбирать свободный порт автоматически | Помогает избежать конфликта локальных портов запускаемых JH |
| TOTP secret | Base32-секрет или otpauth:// URI; не текущий цифровой код |
| Алгоритм / цифры / период | Параметры TOTP сервера; обычно SHA1, 6 цифр, 30 секунд |
| Ожидаемый OTP prompt | Подстрока приглашения, после которой отправляется код |
| Команда после входа | Команда/скрипт получения доступа во внутреннюю сеть |
| Отправить пароль после команды | Повторная отправка пароля SSH-учётки по запросу команды |
| Ожидаемый prompt пароля | Текст запроса именно повторного пароля |
| Таймаут скрипта | Ожидание результата команды доступа, а не срок жизни консоли |
| Механизм контрольных серверов | Обучение на успешных подключениях и проверка сохранения доступа |
| Контрольных серверов | Размер используемого набора проверок |
| Перезапуск по расписанию / интервал | Регулярное повторение команды доступа |

Сначала посмотрите реальную последовательность приглашений в консоли. Не заменяйте все prompts символом `$`: одинаковая короткая подстрока может встретиться не в том месте. Если OTP не принимается, проверьте часы ПК и параметры TOTP до изменения сценария входа.

## Готовность и восстановление

Живой процесс KiTTY или открытый TCP-порт ещё не означает работающий вход. Менеджер проверяет ответ SOCKS5. Если собственный запуск не дал готового входа, может быть выполнено восстановление. Учёт процессов позволяет отличать управляемые консоли от посторонних; не рассчитывайте, что менеджер будет перезапускать все окна, открытые вручную.

Предложение запуска неготовых JH при старте приложения включено по умолчанию и отключается в настройках. Несколько точек входа допустимы; последний рабочий путь влияет на последующий выбор маршрута.

## Команда доступа, контроль и расписание

Отправка команды не равна подтверждённому доступу. Контрольные серверы помогают проверить, появилась ли доступность сети. Наученный набор формируется из реально успешных маршрутов; его статус виден в настройках точки.

Для периодического продления включите расписание и задайте интервал. Успешная проверка уже живого доступа не должна отодвигать просроченный запуск команды. Пока скрипт выполняется, второй запуск параллельно не создаётся. После неудачной/неподтверждённой попытки действует ограничение повторов; смотрите статус и следующий срок, а не отправляйте пароль вслепую в открытый редактор/программу.

**«Сбросить»** очищает обученные контрольные серверы и начинает новый отсчёт; не удаляет саму точку. **«Закрыть лишние консоли»** предназначено для лишних управляемых консолей, не для очистки всех терминалов ОС.

## Типичные проблемы

| Симптом | Что проверить |
|---|---|
| Окно KiTTY есть, вход не готов | SOCKS5-порт, завершение SSH/OTP, разрешение forwarding |
| Постоянно ждёт приглашение | Реальный prompt, раскладку/регистр, необходимость повторного пароля |
| OTP неверен | Синхронизацию времени и secret/алгоритм/цифры/период |
| Доступ пропал после простоя | Срок действия доступа, команду продления, контрольные серверы и журнал |
| После переноса не хватает учётных данных | TOTP и данные назначенных JH очищаются при JSON-экспорте; задайте свои |
