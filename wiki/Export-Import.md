# Экспорт, импорт и синхронизация KiTTY

Есть три разных операции: импорт portable-файлов KiTTY, перенос JSON-конфигурации менеджера и применение различий обратно в KiTTY. Выбирайте их по задаче.

## Перенос JSON

Откройте **«Меню → Экспорт JSON…»**, выберите сессии и необходимость включать точки входа.

| Переносится | Не следует считать перенесённым |
|---|---|
| Выбранные сессии, их веб-интерфейсы и резервные адреса | Локальные настройки exe, Firefox-профиль и таймауты приложения |
| Нужные ветки групп | Сами файлы закрытых ключей и исходные KiTTY-файлы |
| Связи между включёнными серверами | Связи с исключёнными сессиями |
| Целый сохранённый маршрут, если его участники включены | Неполный маршрут со ссылками на исключённые узлы |
| Точки входа при соответствующем выборе | TOTP secret и состояния запусков/успеха JH |

Обычные секреты включённых сессий в экспортном JSON хранятся **открытым текстом**. При этом логин, SSH-пароль, passphrase и Root-пароль сессий, назначенных jumphost, очищаются: получатель задаёт свои данные. После переноса проверьте также TOTP, локальные ключи и команды доступа.

Экспорт — перенос конфигурации, а не полный архив всех файлов приложения. Для отката на том же ПК сохраняйте закрытую папку приложения; для другой учётной записи нужен переносимый JSON.

## Мастер умного импорта

1. Выберите JSON через **«Меню → Импорт JSON…»**.
2. Просмотрите сопоставление групп и сессий. Точное совпадение ID надёжнее, чем похожее имя; один IP не доказывает идентичность серверов в разных сетях.
3. Уточните сомнительные пары вручную. Для групп выберите объединение/имя или отдельную новую группу.
4. Просмотрите решения по сессиям и отдельным полям. Можно оставить текущее значение или принять импортное; добавление новой копии — отдельное решение.
5. Проверьте связанные маршруты/точки входа и итог, затем примените изменения.

Предпросмотр не должен менять живую конфигурацию. Перед применением создаётся backup, при ошибке поддерживается откат. Локальные объекты не удаляются только потому, что их нет во входном файле. Текущий локальный путь ключа по умолчанию не заменяется чужим путём.

## Импорт KiTTY и обратная запись

Импорт папки portable-сессий читает настройки KiTTY, включая поддерживаемые пароли, Autocommand и login script. Проверьте результат: нестандартный скрипт или путь со старого ПК нельзя автоматически считать пригодным.

В **«Меню → Изменения KiTTY…»**:

- **Применить** — записать выбранные значения менеджера в соответствующую KiTTY-сессию.
- **Отклонить** — взять значения KiTTY в менеджер.
- **Игнорировать** — скрыть текущую пару различий, не меняя обе стороны. Если значение изменится снова, различие вернётся.

Опция немедленной записи в KiTTY выполняет запись после сохранения карточки. Менеджер ограничивает такую запись встроенной папкой `KiTTY` рядом с приложением. Исходные portable-файлы не являются неизменяемыми: явное применение действительно их обновляет.

Удаление сессии **из менеджера** оставляет исходную KiTTY-сессию. Удаление группы/подгрупп переносит их сессии в «Без группы». Это не удаление файлов или серверов в сети.

## Безопасный перенос

Экспортируйте на старом ПК → перенесите файл защищённо → импортируйте на новом → задайте локальные пути и данные JH → проверьте одно подключение → удалите ненужную открытую копию экспорта. Не публикуйте экспорт, `Data`, закрытые ключи или личные login scripts вместе с репозиторием.
