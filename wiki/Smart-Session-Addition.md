# Умное массовое добавление SSH-сессий

Инструмент **«Умное массовое добавление сессий»** предназначен для быстрого и безопасного ввода в эксплуатацию пула серверов (от нескольких узлов до десятков и сотен машин) без необходимости ручного создания каждой карточки сессии.

---

## Возможности

- **Пакетный ввод серверов**: IP-адреса, хосты или FQDN списком с любой комбинацией разделителей (переводы строк, запятые, точки с запятой, пробелы), автоматической валидацией и дедупликацией.
- **Гибкий выбор маршрута**: сканирование напрямую с рабочего ПК или через выбранную точку входа (JumpHost) с автоматическим запуском SOCKS5-туннеля при необходимости.
- **Автоматический подбор учётных данных**: перебор заданных списков логинов и паролей с приоритетом уже подтверждённых учётных записей и строгим ограничением неудачных попыток на узел для защиты от `fail2ban`.
- **Глубокое зондирование привилегий**: проверка доступности прав суперпользователя:
  1. Прямой вход под `root` (UID 0).
  2. Беспарольный `sudo` (с предварительным сбросом кэша `sudo -k`).
  3. Парольный `sudo` с подбором пароля из пула кандидатов.
  4. Пароль учётной записи входа проверяется в последнюю очередь.
- **Многоскачковое обнаружение (Multi-hop)**: для серверов в изолированных сегментах сети выполняется поиск маршрута через другие успешно обнаруженные серверы текущего пакета с защитой от циклов и выбором кратчайшего пути.
- **Генерация стандартизированных имён**: сессии автоматически именуются по правилу `Регион Назначение Площадка Номер` (например, `Group Main S1` или `MapServer Reserve S2`) на основе удалённого hostname и подсети. Гарантируется уникальность имён.
- **Интерактивный предварительный просмотр**: редактирование названий, выбор групп, просмотр/копирование паролей с защитой от подглядывания, массовое изменение групп и выборочное сохранение сессий в конфигурацию.

---

## Запуск инструмента

Открыть окно умного добавления можно тремя способами:
1. Кнопка **«Массовое добавление»** в верхней правой панели главного окна.
2. Меню правой кнопки мыши по таблице сессий: **«Умное массовое добавление сессий…»**.
3. Главное меню приложения: **«Меню → Массовое добавление сессий…»**.

Окно является немодальным — вы можете сворачивать его, переключаться на главное окно или продолжать работу с активными SSH-сессиями.

## Входные параметры

### 1. Серверы
В поле ввода укажите адреса целевых серверов. Допускаются:
- IPv4-адреса (например, `192.168.1.10`, `10.20.30.40`).
- Доменные имена и имена хостов (например, `srv-app-main-01.local`, `db01.prod`).
- Разделители: символы перевода строки, запятые, точки с запятой или пробелы.
- Некорректные адреса (например, с недопустимыми октетами или символами) и дубликаты отсеиваются автоматически перед запуском.

### 2. Параметры подключения
- **SSH-порт**: порт SSH-демона на целевых машинах (по умолчанию `22`).
- **Таймаут (сек)**: время ожидания ответа на этапе зондирования порта и SSH-рукопожатия (по умолчанию `5` секунд).
- **JumpHost (точка входа)**:
  - `[Без JumpHost — прямое подключение]` — сканирование производится непосредственно с локального компьютера.
  - Конкретный настроенный JumpHost — сканирование направляется через соответствующий SOCKS5-прокси. Если сервис точки входа не активен, менеджер автоматически запустит его перед началом сканирования.
- **Группа**: выбор группы для создаваемых сессий. Вы можете выбрать существующую группу, верхний уровень `[Без группы]` или ввести новое имя группы (включая подгруппы через слэш, например `Производство/Серверы БД`).

### 3. Учётные данные
- **Логины**: список логинов пользователей для входа по SSH (по одному в строке, например `admin`, `operator`, `ubuntu`).
- **Пароли**: список возможных паролей (по одному в строке).
- **Скрыть пароли**: переключатель скрытия паролей звёздочками (`••••••••`) для защиты от компрометации экрана при демонстрации или записи.

## Многофазный алгоритм сканирования

После нажатия кнопки **«Начать сканирование»** запускается трёхфазный процесс:

### Фаза 1. Проверка доступности портов (TCP Reachability)
Быстрая проверка открытости указанного SSH-порта для каждого хоста из списка. Если порт закрыт или хост не отвечает за время таймаута, он сразу помечается как недоступный и откладывается для третьей фазы (multi-hop).

### Фаза 2. Подбор учётных данных и зондирование системы
Для каждого ответившего хоста:
1. **Аутентификация SSH**:
   - Перебираются пары логин/пароль из введённых списков.
   - Учётные данные, которые уже сработали на предыдущих серверах текущего сканирования, проверяются в первую очередь. Это сокращает время сканирования пула одинаково настроенных машин в несколько раз.
   - Количество неудачных попыток ограничено, что исключает блокировку IP средствами защиты `fail2ban` / `pam_faillock`.
2. **Определение Hostname**:
   - Выполняется опрос реального имени машины через команду `hostname` (или чтение `/etc/hostname`).
   - На основе полученного имени и сетевого адреса генератор имён формирует читаемое и уникальное название сессии.
3. **Зондирование привилегий (Root / sudo)**:
   - Проверяется UID текущего пользователя: если `0`, сервер доступен сразу под `root`.
   - Если пользователь непривилегированный, сбрасывается кэш sudo (`sudo -k`) и выполняется проверка беспарольного доступа `sudo -n id -u`. При успехе устанавливается команда `sudo -i` без пароля.
   - Если требуется пароль, проверяются пароли из пула кандидатов.
   - Пароль текущей учётной записи SSH проверяется в последнюю очередь.

### Фаза 3. Многоскачковое обнаружение (Multi-hop)
Серверы, которые не ответили на прямой зонд в Фазе 1, могут находиться в изолированном сегменте сети за пограничными узлами.
- Для таких серверов алгоритм проверяет возможность перехода через узлы, успешно обнаруженные в Фазе 2.
- Используется обход в ширину (BFS) для нахождения кратчайшего маршрута.
- Встроен алгоритм обнаружения и предотвращения циклических зависимостей.
- При успешном переходе запоминается направленная связь (`ServerLink`), которая будет автоматически создана в менеджере.

## Генератор понятных имён (Smart Naming)

Генератор анализирует токены hostname (разбивая по `-`, `_`, `.`) и IP-адрес:
- **Роль/Назначение**:
  - `group` / `grp` → `Group`
  - `map` / `gis` → `MapServer`
  - `db` / `sql` / `postgres` → `Database`
  - `web` / `www` / `nginx` → `Web`
  - `proxy` / `gate` / `gw` → `Proxy`
  - `backup` / `bak` → `Backup`
- **Площадка**:
  - `main` / `pri` / `primary` / `m` → `Main`
  - `reserve` / `res` / `sec` / `backup` / `b` → `Reserve`
- **Идентификатор узла**: токены вида `s1`, `node2`, `srv03` преобразуются в `S1`, `Node2`, `Srv03`.
- **Регион**: сопоставляется с целевой группой или подсетью IP-адреса.
- **Уникальность**: если сессия с таким именем уже существует в конфигурации или текущем списке кандидатов, к имени добавляется суффикс `(2)`, `(3)` и т.д.

При необходимости любое сгенерированное имя можно отредактировать прямо в таблице кандидатов перед созданием сессий.

## Работа с результатами

Интерфейс разделен на две вкладки:

### Вкладка «Найденные сессии»
Содержит успешно распознанные узлы, готовые к добавлению:
- Флажок выбора (для выборочного создания).
- **Название**: редактируемое имя сессии.
- **Хост и Порт**: сетевые реквизиты.
- **Логин и Пароль**: рабочие учётные данные. Пароль можно скопировать через контекстное меню.
- **Root-команда и Root-пароль**: результаты зондирования привилегий.
- **Группа**: целевая группа для данного сервера.
- **Маршрут**: прямой или цепочка через промежуточные узлы. Кнопка **«Связи»** позволяет просмотреть детали маршрута.

### Вкладка «Проблемные узлы»
Отображает серверы, подключение к которым завершилось ошибкой:
- Указывается причина сбоя: таймаут, отклонение аутентификации, закрытый порт и т.д.
- Кнопка **«Повторить для проблемных»** перезапускает сканирование только для неответивших узлов (например, после включения VPN или исправления паролей).

### Массовые действия
- **Применить группу к выбранным**: позволяет выделить несколько строк в таблице кандидатов и сменить им группу в одно действие.
- **Создать сессии**: добавляет все отмеченные галочками кандидаты в менеджер. Автоматически создаются:
  1. Записи `ManagedServer` с заполненными реквизитами, паролями и настройками повышения прав.
  2. Необходимые группы и подгруппы.
  3. Направленные связи (`ServerLink`) для серверов, требующих перехода через промежуточные узлы.
  4. Конфигурация сохраняется в `Data/config.json`, а дерево сессий в главном окне обновляется немедленно.

## Безопасность

1. **Защита от подглядывания (Shoulder Surfing)**: поле ввода паролей и отображение паролей в таблице поддерживают маскирование.
2. **Шифрование DPAPI**: при сохранении сессий все пароли (учётных записей и root) шифруются стандартным криптографическим механизмом Windows DPAPI текущего пользователя.
3. **Безопасная отмена**: процесс сканирования можно в любой момент прервать кнопкой **«Отмена»**. Все серверы, успевшие пройти проверку до нажатия отмены, сохраняются в списке кандидатов и доступны для создания сессий.
