# KiTTY Manager — установка и первоначальная настройка

Эта инструкция объясняет установку с нуля, перенос существующих сессий KiTTY, настройку точек
входа, построение связей и открытие веб-интерфейсов.

## 1. Что делает программа

KiTTY Manager хранит SSH-сессии и помогает подключаться к серверам, к которым нет
прямого доступа.

Например, сервер `C` может быть доступен только по цепочке:

```text
ваш компьютер → точка входа (JH) → сервер A → сервер B → сервер C
```

Менеджер запоминает найденные связи и при следующем подключении сначала пробует
уже известный рабочий маршрут.

Для работы используются:

- **KiTTY** — открывает SSH-консоли;
- **Firefox** — открывает внутренние веб-интерфейсы;
- **KiTTY Manager** — хранит настройки и строит маршруты.

Программа портативная: устанавливать её в Windows не требуется.

## 2. Важные предупреждения

Перед началом работы учтите следующее:

1. Пароли, пароли ключей, root-пароли, TOTP secret и сохранённые login script
   в `Data\config.json` зашифрованы средствами Windows для текущей учётной записи.
2. Такой `config.json` нужно открывать той же учётной записью Windows на том же
   компьютере. Простого копирования на другой компьютер недостаточно.
3. JSON-экспорт специально остаётся переносимым и содержит включённые в него
   секреты открытым текстом.
4. Храните папку менеджера и экспортные файлы только в защищённом месте.
5. Не отправляйте `config.json` и JSON-экспорт посторонним.
6. Перед переносом или крупным изменением создавайте резервную копию.

При первом запуске новой версии старый `config.json` с открытыми секретами будет
автоматически перезаписан в зашифрованном виде. Если Windows не сможет
расшифровать файл, менеджер покажет ошибку и закроется, не затирая конфигурацию.

## 3. Чистая установка без старых сессий KiTTY

Если переносить старые сессии KiTTY не нужно:

1. Распакуйте `kitty-manager-windows-x64.zip` в отдельную папку.
2. Не запускайте программу прямо из ZIP-архива.
3. Запустите `KiTTYManager.exe`.
4. Откройте **Настройки**.
5. Проверьте пути к KiTTY и Firefox.
6. Настройте точки входа и создайте SSH-сессии по разделам ниже.

Рекомендуется использовать папку без кириллицы и без ограничений на запись,
например:

```text
C:\Tools\KiTTYManager
```

## 4. Перенос существующих сессий KiTTY

Этот раздел нужен только в том случае, если у вас уже есть настроенная KiTTY.

### Рекомендуемый вариант: один раз импортировать и дальше хранить сессии в менеджере

Такой вариант проще: после переноса главным источником данных будет менеджер, а
встроенная KiTTY будет использоваться как средство подключения.

### Шаг 1. Сделайте резервную копию старой KiTTY

Полностью скопируйте рабочую папку KiTTY в безопасное место.

Не используйте резервную копию для экспериментов. Она должна остаться нетронутой,
чтобы к ней можно было вернуться.

### Шаг 2. Подготовьте временную копию менеджера

1. Распакуйте `kitty-manager-windows-x64.zip`.
2. Найдите внутри папку `KiTTY`.
3. Скопируйте файлы сохранённых сессий в:

```text
KiTTY\Sessions
```

Если ваши сессии используют отдельные login script, относительные ключи или другие
файлы из папки KiTTY, временно сохраните и их прежнюю структуру каталогов.

Менеджер поставляется с проверенной версией KiTTY. Не заменяйте `kitty.exe` более
новой или старой версией без отдельного тестирования.

### Шаг 3. Выполните первый импорт

1. Запустите `KiTTYManager.exe`.
2. При первом запуске менеджер просканирует `KiTTY\Sessions`.
3. Найденные сессии появятся в списке менеджера.
4. Проверьте несколько сессий:
   - адрес;
   - SSH-порт;
   - логин;
   - обычный пароль;
   - команду повышения прав;
   - root-пароль;
   - резервные адреса, если они использовались.

Сам импорт не изменяет исходные файлы сессий KiTTY.

### Шаг 4. Создайте JSON-экспорт

1. Откройте меню **…**.
2. Нажмите **Экспорт JSON…**.
3. Выберите все нужные сессии.
4. Если уже настроены точки входа и их тоже нужно перенести, включите их в экспорт.
5. Сохраните файл в защищённом месте.

> JSON-экспорт содержит пароли открытым текстом.

### Шаг 5. Создайте чистую рабочую копию

1. Закройте менеджер через **… → Выйти**.
2. Не удаляйте резервную копию старой KiTTY и созданный JSON.
3. Распакуйте `kitty-manager-windows-x64.zip` ещё раз в новую пустую папку.
4. Запустите чистый менеджер.
5. Откройте **… → Импорт JSON…**.
6. Выберите созданный экспорт.
7. Проверьте количество импортированных сессий.

Теперь сессии хранятся в конфигурации менеджера. Встроенная KiTTY используется для
открытия консоли и не обязана содержать отдельную сохранённую копию каждой сессии.

После переноса повторно проверьте:

- локальные пути к KiTTY, Firefox и ключам;
- TOTP secret точек входа;
- настройки Firefox;
- автоматически запускаемые точки входа.

Локальные настройки приложения и TOTP secret намеренно не переносятся обычным
экспортом как готовые настройки другого компьютера.

## 5. Основные поля SSH-сессии

Для каждой сессии заполните:

- **Название** — понятное имя, например `Сервер приложений`;
- **Адрес** — IP-адрес или DNS-имя без `ssh://`;
- **SSH-порт** — обычно `22`;
- **Логин** — учётная запись для первого входа;
- **Пароль** — пароль этой учётной записи;
- **Ключ SSH** — путь к PPK/PEM-ключу, если он используется;
- **Пароль ключа** — passphrase закрытого ключа;
- **Повышение прав** — например `su -` или `sudo -i`;
- **Root-пароль** — пароль, который запрашивает команда повышения прав;
- **Shell prompt** — устойчивая часть приглашения командной строки;
- **Команда KiTTY** — команда, которую исходная сессия выполняет после входа.

Нажмите **Сохранить изменения**.

Подробное описание всех полей находится в **… → Справка по полям…**.

### Резервные адреса

Если один сервер доступен по нескольким адресам или портам из разных подсетей, добавьте основной и
резервные `ip:port`.

Менеджер запоминает рабочий адрес отдельно для каждого участка маршрута. Если
основной адрес временно недоступен, будет проверен резервный.

### Одинаковые private IP в разных сетях

Иногда адрес вроде `192.168.1.10` существует сразу в нескольких проектах, но
это разные серверы в изолированных сетях. Обычная автоматическая проверка может
успешно попасть по этому адресу через неправильную точку входа.

Для нужной целевой сессии выберите поле **Маршрут через** и укажите сервер,
который изначально должен находиться непосредственно перед ней. Например:

```text
JH → внешний сервер проекта → 192.168.1.10
```

После сохранения менеджер не будет пробовать цель напрямую через JH. Другой
промежуточный сервер станет допустим только после того, как вы проверите и
успешно построите именно его связь с целью. Это позволяет перейти на новый
короткий путь после изменения сети, но не даёт случайно попасть на такой же IP
другого проекта. Значение **Автоматически (без ограничения)** сохраняет
обычное поведение.

Если сервер действительно доступен прямо с рабочего компьютера, включите
**Сначала подключаться напрямую, без JH**. Тогда прямой SSH проверяется первым,
а сохранённые связи и JH остаются резервными. Для повторяющихся внутренних IP
эту настройку не используйте — там безопаснее явно указать **Маршрут через**.

## 6. Настройка точки входа (JH)

Точка входа — сервер, через который менеджер получает доступ к остальной сети.

### Шаг 1. Создайте обычную сессию JH

Сначала настройте JH как обычную SSH-сессию:

- адрес и порт JH;
- логин;
- пароль или ключ;
- остальные данные, необходимые для входа.

Сохраните сессию и убедитесь, что она открывается.

### Шаг 2. Добавьте точку входа

1. Нажмите **Настроить точки входа**.
2. Добавьте новую точку.
3. В поле **Сессия jumphost** выберите созданную сессию JH.
4. Для автоматически создаваемого SOCKS5 обычно используйте адрес:

```text
127.0.0.1
```

5. Рекомендуется включить автоматический выбор свободного порта.
6. Включите автоматический запуск JH, если менеджер должен запускать её сам.

### Если JH запрашивает одноразовый код

Заполните:

- **TOTP secret** — Base32-секрет или полный `otpauth://` URI;
- алгоритм;
- количество цифр;
- период;
- текст ожидаемого OTP prompt.

Параметры должны совпадать с приложением, которое раньше генерировало код.

### Если после входа нужна команда доступа

Укажите:

- команду после входа, например `./open_access.sh`;
- ожидаемый prompt;
- нужно ли повторно отправлять пароль учётной записи;
- время ожидания после запуска.

Точек входа может быть несколько. Менеджер запоминает наиболее подходящую JH
отдельно для каждой целевой сессии.

## 7. Группы и подгруппы

Группы нужны для порядка и массового построения связей.

Пример:

```text
Проект
├── Основные серверы
└── Резервные серверы
```

Чтобы переместить сессию, перетащите её мышью в нужную группу.

Можно создать одну заполненную эталонную сессию, дублировать её и менять у копий
название, адрес, логин и пароли. После дублирования обязательно проверьте:

- команду KiTTY;
- повышение прав;
- путь к ключу;
- резервные адреса;
- веб-интерфейсы.

## 8. Построение связей

Связь означает, что с одного сервера можно подключиться к другому.

### Проверка от одной сессии

1. Выберите исходную сессию.
2. Нажмите **Проверить доступ к другим серверам…**.
3. Выберите одну или несколько целей.
4. Подтвердите запуск.

Менеджер сначала проверяет одно направление. Если оно не сработало, проверяет
обратное. Один успешный результат сохраняет пару как доступную сразу в обе
стороны.

### Массовая проверка внутри группы

1. Нажмите правой кнопкой по группе.
2. Выберите **Построить карту связей внутри группы…**.
3. Проверьте список пар и подтвердите запуск.

Каждая пара проверяется одним проходом. Массовая проверка может создать много
SSH-входов. Перед запуском убедитесь, что логины и пароли верны, иначе сервер
может временно заблокировать учётную запись.

Если в уже настроенную группу добавили новую сессию, выберите
**Построить только недостающие связи…**. Менеджер не будет повторно
проверять уже сохранённые пары, но будет использовать известные маршруты
как опору для поиска новых связей.

Если напрямую доступен не сервер этой группы, а только длинный сохранённый путь
до одного из её серверов, менеджер использует его как удалённую опору. Он один
раз открывает всю известную цепочку до опоры, из неё проверяет остальные серверы
группы, а затем допроверяет только ещё не найденные пары. Уже успешные пары и
одинаковые длинные входы повторно не запускаются.

## 9. Карта связей

Откройте **… → Карта связей…**.

На карте отображаются только сессии, у которых уже есть хотя бы одна сохранённая
связь.

Обозначения:

- синяя линия — есть подтверждённая рабочая связь;
- оранжевая пунктирная линия — связь сохранена, но сейчас не имеет подтверждённого
  успешного состояния;
- жёлтые линии — связи выбранной сессии;
- жёлтые рамки — сессии, связанные с выбранной.

Управление:

- перетаскивание пустого места двигает карту;
- колесо мыши изменяет масштаб;
- кнопки `−` и `+` также изменяют масштаб;
- **Вся карта** возвращает общий вид;
- обычный клик по карточке выбирает эту сессию в главном окне.

### Построение новых связей с карты

1. Нажмите **Проверка связей**.
2. Выберите не менее двух карточек. Сессию, которой ещё нет на карте,
   добавьте кнопкой **Добавить сессию…** — в выпадающем списке есть поиск,
   список не закрывается после выбора, а повторный клик снимает отметку.
3. Нажмите **Проверить выбранные**.

Менеджер проверит возможные пары выбранных сессий.

Настройка **В режиме карты проверять только новые связи** по умолчанию включена.
При ней уже сохранённые пары пропускаются. Обычные проверки вне карты могут
повторно проверить существующую связь.

Даже если на карте пока нет ни одной сессии, через список можно добавить две любые
сессии и запустить проверку.

## 10. Настройка Firefox и веб-интерфейсов

Менеджер создаёт SSH-маршрут до выбранной сессии, поднимает отдельный динамический
SOCKS5 и запускает через него Firefox.

### Подготовьте шаблон Firefox

1. Откройте обычный Firefox.
2. Настройте его так, как требуется для внутренних веб-сайтов.
3. Введите в адресной строке:

```text
about:support
```

4. Найдите поле **Папка профиля**.
5. В настройках KiTTY Manager укажите эту папку как шаблон профиля Firefox.

Менеджер копирует шаблон, но не изменяет оригинальный профиль.

### Временные и постоянные профили

- **Временные профили** удаляются после закрытия Firefox и занимают меньше места
  со временем.
- **Постоянные профили** запоминают принятые сертификаты и настройки сайта.
- Настройка одного профиля на группу экономит место, но не подходит для
  одновременной работы с разными туннелями внутри одной группы.

### Добавьте веб-интерфейс

1. Откройте карточку SSH-сессии.
2. В разделе **Веб-интерфейсы** нажмите **Добавить**.
3. Укажите название и полный URL, например:

```text
https://192.0.2.20:8443/
```

4. При необходимости сохраните логин и пароль как подсказку.
5. Сохраните изменения.
6. Нажмите **Открыть веб-интерфейс**.

Firefox не вводит сохранённые логин и пароль автоматически.

Для каждого веб-туннеля выбирается отдельный свободный локальный порт. Поэтому
веб-интерфейсы разных сетей, в том числе с одинаковыми внутренними IP-адресами,
могут работать одновременно.

## 11. Ежедневная работа

Обычный порядок работы:

1. Запустите KiTTY Manager.
2. Выберите нужную сессию.
3. Нажмите **Подключиться** или дважды щёлкните по сессии.
4. Менеджер сначала попробует ранее запомненный рабочий маршрут.
5. Если он недоступен, будут проверены сохранённые связи и другие точки входа.
6. Для веб-сайта выберите нужный веб-интерфейс и откройте его.

Если сохранённая связь начинается с внутреннего сервера, менеджер не считает
его автоматически доступным прямо от JH. Он либо использует ранее доказанный
прямой вход, либо подставляет целиком сохранённую цепочку до этого сервера.
Поэтому рабочий длинный путь не заменяется коротким предположением.

У обычной открытой консоли нет таймера автоматического отключения. Консоль,
которая успешно подключилась напрямую без JH, также передаётся самой KiTTY и
продолжает работать после закрытия менеджера.

Если менеджер свёрнут в трей, обслуживаемые маршруты продолжают работать. Полный
выход из менеджера завершает автоматические маршруты и туннели.

## 12. Изменения KiTTY

Менеджер может хранить изменения только в своей конфигурации или дополнительно записывать их во
встроенную KiTTY.

В настройках есть опция **Записывать изменения сразу в KiTTY**.

В разделе **… → Изменения KiTTY…**:

- **Применить** — записать значение менеджера во встроенную KiTTY;
- **Отклонить** — вернуть в менеджер значение из KiTTY;
- **Игнорировать** — скрыть только текущее различие.

Если проигнорированное поле изменится повторно, новое различие снова появится.

Запись ограничена встроенной папкой KiTTY рядом с менеджером и не должна менять
другие копии KiTTY в системе.

## 13. Резервное копирование

Для резервной копии используйте **… → Экспорт JSON…**.

Экспорт может содержать:

- сессии;
- группы;
- резервные адреса;
- сохранённые связи;
- кэш известных рабочих маршрутов;
- выбранные точки входа без переносимых TOTP-секретов.

После экспорта:

1. Проверьте, что файл создан.
2. Храните его в защищённом месте.
3. Не отправляйте его через незащищённые каналы.
4. После восстановления проверьте локальные пути, TOTP и настройки приложения.

## 14. SSH host key

SSH host key подтверждает, что вы подключаетесь к нужному серверу.

Новый ключ может быть принят автоматически, если соответствующая настройка
включена. Изменившийся ключ не должен приниматься автоматически.

Если ключ изменился неожиданно:

1. не продолжайте подключение вслепую;
2. сравните fingerprint с данными администратора;
3. только после проверки принимайте новый ключ.

Параметр `loghost` используется как постоянное логическое имя настоящего сервера.
Он не закрепляет локальный TCP-порт.

## 15. Если подключение не работает

Проверьте по порядку:

1. Правильно ли указан основной адрес и SSH-порт.
2. Есть ли корректный резервный адрес.
3. Работает ли выбранная JH.
4. Запущен ли локальный SOCKS5 точки входа.
5. Верны ли логин, пароль и ключ.
6. Не заблокирована ли учётная запись после нескольких неудачных входов.
7. Правильно ли заполнены TOTP и prompt.
8. Существует ли сохранённая связь до целевого сервера.
9. Не устарел ли SSH host key.

Для диагностики можно временно включить журнал работы, повторить одну проблемную
операцию и затем открыть папку журналов через меню **…**.

Не публикуйте журнал без проверки: в нём не должны специально записываться
секреты, но он может содержать внутренние имена серверов, адреса и структуру сети.

## 16. Где найти дополнительную помощь

- **… → Справка по полям…** — описание всех полей и настроек;
- **Сохранённые связи…** — связи конкретной сессии;
- **… → Карта связей…** — общий граф;
- **… → Открыть папку журналов…** — диагностические журналы.
