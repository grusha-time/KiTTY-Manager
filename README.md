# KiTTY Manager 2.1

KiTTY Manager — приложение Windows для SSH-сессий. Оно хранит серверы в группах, находит путь через точки входа и промежуточные серверы, открывает терминал KiTTY, SFTP в WinSCP и веб-панели в Firefox. Для повторяющихся операций есть конструктор массовых задач и встроенный Ansible.

## С чего начать

1. Скачайте **`KiTTYManager-2.1.1-windows-x64.zip`** из [Releases](https://github.com/grusha-time/KiTTY-Manager/releases), распакуйте в доступную для записи папку, например `C:\Tools\KiTTYManager`.
2. Запустите `KiTTYManager.exe`. Устанавливать .NET отдельно для готового ZIP не нужно.
3. Создайте сессию или импортируйте папку portable-сессий KiTTY. Укажите адрес, SSH-порт, логин и пароль/ключ, сохраните карточку.
4. Если сервер доступен с ПК, включите **«Сначала подключаться напрямую, без JH»**. Если нужен вход через другую сеть, настройте [точку входа](https://github.com/grusha-time/KiTTY-Manager/wiki/Jumphost).
5. Двойной клик по сессии (или выбор стрелками и нажатие Enter) выполняет умное подключение. Нажатие Ctrl+F в главном окне фокусирует поиск сессий, стрелка ↓ переходит к результатам, а клавиша Esc или кнопка очистки сбрасывают запрос. Для открытия исходной сессии есть отдельное действие **«Открыть напрямую в KiTTY»**.

Полная [установка и первый запуск](https://github.com/grusha-time/KiTTY-Manager/wiki/Installation) объясняют оба варианта подключения, обновление и перенос данных. [Главная страница руководства](https://github.com/grusha-time/KiTTY-Manager/wiki/Home) помогает выбрать нужный раздел. В приложении есть **«Меню → Справка по полям…»** с поиском по всем разделам (`Ctrl+F`).

## Что входит в ZIP

- `KiTTYManager.exe` — приложение со встроенным .NET runtime.
- `KiTTY/` — portable KiTTY, её настройки и лицензия.
- `Runtime/Ansible/` — QEMU, Linux runtime, Ansible и лицензии компонентов.

Firefox и WinSCP **не входят** в ZIP: установите их отдельно, если нужны соответствующие функции. Для SSH-консолей они не требуются. Для Ansible нужна работоспособная виртуализация Windows/WHPX; кнопка готовности находится в режиме Ansible. Файлы пользовательских сессий и учётные данные в дистрибутив не включены. Документация и [учебные задачи](examples/batch-tasks/README.md) находятся в репозитории и не входят в релизный ZIP. Для чтения и запуска примеров без доступа к GitHub заранее скачайте исходники репозитория целиком. «Справка по полям» встроена в приложение и доступна без этих файлов.

## Важные особенности

- Конфигурация хранится рядом с приложением в `Data/`. Не запускайте менеджер прямо из архиватора или из папки без права записи.
- Секретные поля `config.json` защищены Windows DPAPI. Для другого компьютера/учётной записи используйте JSON-экспорт: в нём секреты **открытые**, такой файл нельзя публиковать.
- Автоматическое доверие новым и изменённым SSH host key по умолчанию включено. Для ручной сверки отпечатков отключите его в настройках.
- Постоянный профиль Firefox сохраняет новые пароли и исключения сертификатов внутри менеджера. Обратной синхронизации с личным профилем нет.
- Полный выход из менеджера закрывает обслуживаемые им маршруты. Сворачивание в трей оставляет их работающими.

## Если что-то не работает

Откройте [разбор типичных проблем](https://github.com/grusha-time/KiTTY-Manager/wiki/Troubleshooting). Перед отправкой журнала включите логирование, повторите проблему и проверьте файл на внутренние адреса и секреты ваших команд. Успешная сборка или тесты ядра не заменяют проверку конкретного Windows/SSH-стенда.

Разработчикам: [архитектура](https://github.com/grusha-time/KiTTY-Manager/wiki/Architecture), [сборка и упаковка](https://github.com/grusha-time/KiTTY-Manager/wiki/Building), [автотесты](https://github.com/grusha-time/KiTTY-Manager/wiki/Testing). GitHub-публикация и локальная сборка — отдельные действия.
