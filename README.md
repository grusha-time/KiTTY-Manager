# KiTTY Manager

Portable Windows-менеджер SSH-сессий для KiTTY с автоматическим построением маршрутов через jumphost-серверы.

![.NET](https://img.shields.io/badge/.NET-8.0-512BD4) ![Platform](https://img.shields.io/badge/platform-Windows-blue) ![License](https://img.shields.io/badge/license-MIT-green)

## Возможности

- **Дерево проектов** — группы и подгруппы сессий с drag-and-drop
- **Импорт KiTTY-сессий** — автоматическое сканирование `KiTTY\Sessions`
- **Умная маршрутизация** — граф SSH-связей, автоматический выбор лучшего пути
- **SOCKS5 jumphost-точки** — с TOTP (SHA1/SHA256/SHA512), access-скриптами и автостартом
- **Карта связей** — интерактивный граф с проверкой пар серверов
- **Веб-интерфейсы** — открытие через SSH-туннель с отдельным Firefox-профилем
- **Внутренний DNS** — резолвинг доменов через SSH-маршрут без правки `hosts`
- **Резервные адреса** — разные ip:port для прямого входа и из подсети
- **Экспорт/импорт** — перенос конфигурации между компьютерами
- **Шифрование секретов** — DPAPI, пароли и TOTP никогда не пишутся в лог

## Быстрый старт

1. Скачайте `kitty-manager-windows-x64.zip` из [Releases](../../releases)
2. Распакуйте в каталог, доступный только вам (например `C:\Tools\KiTTYManager`)
3. Запустите `KiTTYManager.exe`
4. Настройте точки входа: **Настроить точки входа** → добавьте SOCKS5 или назначьте сессию jumphost
5. Создайте группы (ПКМ) и перетащите в них сессии
6. Подключайтесь двойным кликом — менеджер сам выберет маршрут

> **Примечание:** исходный код KiTTY не включён в репозиторий. Он доступен на
> [github.com/cyd01/KiTTY](https://github.com/cyd01/KiTTY) (версия 0.76.1.13).
> Для сборки пакета скачайте `kitty_portable-0.76.1.13.exe` и поместите в `downloads/`.

## Как работает маршрутизация

При подключении менеджер решает две задачи:

| Задача | Что делает |
|--------|-----------|
| **Маршрут** | Выбирает цепочку серверов: JH → A → B → цель |
| **Адрес** | Для каждого хопа подбирает ip:port (основной или резервный) |

### Порядок выбора маршрута

1. Последний успешный кандидат
2. Проверенные сохранённые связи
3. Остальные прямые JH и непроверенные пути

Ранжирование внутри класса:
- Сложность точки входа (без OTP/скрипта проще)
- Суммарная задержка связей
- Число переходов
- Свежесть последнего успеха

### Память маршрутов

Менеджер запоминает для каждого сервера:

- **PreferredRoute** — последняя успешная цепочка + задержка
- **PreferredProxyId** — лучшая точка входа для этой цели
- **EndpointPreferences** — рабочий ip:port для каждого контекста (`JH → сервер`, `сервер A → сервер B`)

Данные сохраняются в `Data\config.json` и переживают перезапуск.

### Фоновые проверки

После успешного обходного подключения менеджер в фоне допроверяет:
- Более быстрые маршруты (если они ожили)
- Прямой доступ (если ещё не подтверждён)

Таймеров в простое нет — проверки запускаются только по событию.

## Точки входа (Jumphost)

Каждая точка входа — это либо:
- Назначенная сессия KiTTY с автостартом
- Внешний SOCKS5 без управляемой сессии

### Поддерживаемые функции

| Функция | Описание |
|---------|----------|
| TOTP | SHA1/SHA256/SHA512, 6–8 цифр, настраиваемый период |
| Access-скрипт | Команда после входа с ожиданием prompt |
| Повтор пароля | Автоматический ввод после скрипта |
| Автостарт | Запуск JH при старте менеджера |
| Плановый перезапуск | Будильник от последнего подтверждённого запуска |

Текущий TOTP-код и оставшееся время отображаются в таблице точек входа.

### Управление консолями

- Менеджер отслеживает свои KiTTY-консоли по PID и заголовку окна
- После перезапуска узнаёт их и не открывает дубли
- Консоль с чужим заголовком предлагает выбор: использовать / отдельная / отмена
- Кнопка «Закрыть лишние консоли» убирает дубли

## Карта связей

Откройте **… → Карта связей…**

### Обозначения

| Цвет | Значение |
|------|----------|
| 🔵 Синяя линия | Подтверждённая рабочая связь |
| 🟠 Оранжевая пунктирная | Связь сохранена, но не подтверждена |
| 🟡 Жёлтые дуги | Связи выбранной сессии |

### Управление

- Перетаскивание — двигает карту
- Колесо мыши / кнопки `−` `+` — масштаб
- «Вся карта» — автоматический масштаб
- Клик по карточке — выбор сессии в главном окне

### Проверка связей

1. Нажмите **Проверка связей**
2. Отметьте ≥ 2 сессии (на карте или через список с поиском)
3. Нажмите **Проверить выбранные**

Для группы: ПКМ → **Построить карту связей внутри группы…** — проверяет каждую пару до первого успеха.

## Резервные адреса

Для серверов, доступных по разным портам из разных сетей:

```
Основной:  10.0.0.5:22     (прямой вход через JH)
Резервный: 10.0.0.5:2222   (из подсети, с соседнего сервера)
```

Менеджер запоминает рабочий адрес **отдельно для каждого контекста**:
- `JH → сервер`
- `сервер A → сервер B`

## Веб-интерфейсы

Для каждой сессии можно добавить веб-интерфейсы:

- Открываются через SSH-туннель в отдельном временном Firefox-профиле
- Логин/пароль сохраняются как подсказка (Firefox не подставляет автоматически)
- Внутренний DNS (опционально): домены резолвятся через SSH-маршрут
- HTTPS остаётся сквозным — менеджер не расшифровывает трафик

## Экспорт / Импорт

### Экспорт (`… → Экспорт JSON…`)

Включает:
- ✅ Сессии + веб-интерфейсы + секреты
- ✅ Группы (только ветки с выбранными сессиями)
- ✅ Связи (только если оба сервера выбраны)
- ✅ Резервные адреса

Не включает:
- ❌ Настройки приложения (пути, таймаут)
- ❌ TOTP-секреты точек входа

### Импорт

- Текущая конфигурация не стирается
- Конфликты показываются таблицей с выбором: оставить текущее / принять из файла

## Сборка из исходников

### Требования

- .NET 8 SDK (или `scripts/project-source.sh install` для локальной установки)
- `kitty_portable-0.76.1.13.exe` в `downloads/`
- `jar` (из JDK) для создания ZIP

### Команды

```bash
# Установка .NET SDK и NuGet-пакетов
./scripts/project-source.sh install

# Сборка + запуск тестов
./scripts/project-source.sh check

# Сборка дистрибутива (dist/kitty-manager-windows-x64.zip)
./packaging/build-package.sh

# Архив исходников без build-артефактов
./scripts/project-source.sh pack
```

### Структура проекта

```
src/
├── KiTTYManager.App/       # WPF GUI
├── KiTTYManager.Core/      # Логика: маршрутизация, SOCKS5, KiTTY-интеграция
└── KiTTYManager.SelfTest/  # Offline-тесты + диагностика
packaging/                  # Скрипты сборки, kitty.ini, sample-config
scripts/                    # project-source.sh (install/check/pack)
vendor/                     # KITTY-LICENCE.TXT
```

## Тестирование

```bash
# Windows (в папке с KiTTYManager.SelfTest.exe)
run-tests.cmd
```

Тесты выполняются без реальных SSH-подключений. Отчёт создаётся в `TestResults\kitty-manager-tests-*.txt` и не содержит адресов, логинов или паролей.

## Безопасность

- Пароли и TOTP-секреты шифруются **DPAPI** (привязка к учётной записи Windows)
- `config.json` нельзя открыть на другом компьютере без дешифрования
- JSON-экспорт содержит секреты открытым текстом — храните в защищённом месте
- Журнал по умолчанию отключён; при включении секреты в него не пишутся
