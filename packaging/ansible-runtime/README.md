# Подготовка встроенного Ansible runtime

Это инструкция для сборки дистрибутива, не для конечного пользователя. Пользователь готового ZIP проверяет виртуализацию через окно готовности в менеджере; ему не нужно устанавливать Python на Windows или собирать Linux-образ.

## Контракт комплекта

Упаковщик ожидает `vendor/ansible-runtime` (каталог исключён из git репозитория из-за размера образа ~384 МБ, как и portable KiTTY):

- QEMU для Windows x64 с WHPX;
- ядро/initramfs и базовый Linux-образ;
- Python и фиксированный ansible-core 2.16.x внутри образа;
- guest-agent и callback, согласованные с кодом менеджера;
- manifest с точными SHA-256 и реальные лицензии распространяемых компонентов.

Текущий сборочный скрипт готовит Alpine Linux, ansible-core 2.16.1 и RAW/ext4 base image. При запуске менеджер создаёт временный qcow2 overlay. Путь serial/named pipe передаёт управление и материалы; SSH идёт отдельно через пробросы менеджера.

## Собрать из исходных компонентов

Из корня проекта в подходящем Linux-окружении:

```sh
bash packaging/build-ansible-runtime.sh
```

Скрипт скачивает компоненты, проверяет заданные контрольные суммы, готовит rootfs/образ и лицензии, создаёт manifest. Ему нужны доступ к сети, инструменты работы с архивами/ext4, возможность chroot/mount и соответствующие права. Это не часть обычной сборки WPF.

Результат — `build/ansible-runtime/output`. Скрипт использует рабочие `build/ansible-runtime`, `downloads/ansible-runtime`, `.tools/ansible-runtime`; временные каталоги подготовки могут очищаться. Перед заменой уже используемого runtime сохраните его отдельно и согласуйте версии guest-agent/протокола.

## Импортировать готовый комплект

```sh
bash packaging/prepare-ansible-runtime.sh /path/to/prepared-runtime
```

Команда проверяет источник и копирует его в `vendor/ansible-runtime`. Если целевая папка уже существует, она откажется перезаписывать её. Не удаляйте рабочую копию, пока новый комплект не проверен.

## Проверить

```sh
python3 packaging/verify-ansible-runtime.py vendor/ansible-runtime
```

Проверяются пути, роли компонентов, фиксированная версия, лицензии, состав и SHA-256. `manifest.example.json` показывает структуру, но не заменяет настоящий manifest. Нулевые и вымышленные hashes непригодны. Проверка повторяется упаковщиком до и после копирования в ZIP.

Файловая целостность не доказывает, что VM запустится через WHPX на конкретном ПК. После изменения runtime обязательны Windows-проверка готовности, playbook с передачей файлов/выгрузкой и проверка остановки VM. [Пользовательские особенности Ansible](../../wiki/Batch-Tasks.md).
